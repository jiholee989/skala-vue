# Weather Dashboard

Vue 3와 OpenWeather API를 활용한 지역별 날씨 대시보드입니다. 국내 10개 도시의 현재 날씨를 조회하고 검색, 필터링, 날씨 지도, 상세 정보 기능을 제공합니다.

> Link: skala-vue-self-three.vercel.app

## 주요 기능

- 국내 10개 도시의 현재 날씨 조회
- 도시 이름 검색, 체감온도와 습도 기준 상세 검색
- 섭씨(℃)·화씨(℉) 단위 전환
- 날씨 상세 보기 - 기온, 날씨, 습도, 풍속, 대기질, 미세먼지, 초미세먼지 조회
- 날씨 지도 - 간략한 한국 지도에서 도시별 위치와 현재 기온 확인

## 화면 구성

| 화면          | 주요 기능                                                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 날씨 대시보드 | 도시 이름 검색, 상세 조건 검색 기능을 제공하며, 국내 10개 도시의 현재 날씨를 카드 형태로 보여줍니다.                          |
| 전국 날씨     | 국내 10개 도시의 위치와 현재 기온을 간략한 지도 형태로 보여줍니다. 도시를 선택하면 해당 도시의 상세 날씨 화면으로 이동합니다. |
| 날씨 상세보기 | 선택한 도시의 기온, 체감온도, 날씨, 습도, 풍속과 함께 대기질, 미세먼지 및 초미세먼지 정보를 제공합니다.                       |
| 서비스 소개   | Weather Dashboard 애플리케이션에서 제공하는 주요 서비스를 안내합니다.                                                         |
| 404           | 존재하지 않는 주소나 도시로 접근했을 때 안내 화면을 표시합니다.                                                               |

## 실행 방법

의존성을 설치합니다.

```
npm install
```

프로젝트 루트에 `.env` 파일을 생성하고 OpenWeather API Key를 설정합니다.

```
VITE_OPENWEATHER_API_KEY=발급받은_API_KEY
```

개발 서버를 실행합니다.

```
npm run dev
```

프로덕션 빌드를 확인합니다.

```
npm run build
```

# 과제별 구현

## Part 1. Weather Mockup

### 핵심 구현

- `v-for`와 `:key`로 날씨 카드 반복 출력
- `v-if`로 기온에 따른 상태 배지 표시
- 한글 검색 입력과 카드 선택 이벤트 구현
- `click.stop`으로 상세보기 버튼의 이벤트 버블링 방지

### 추가 기능

- 체감온도, 습도, 미세먼지 데이터와 도시 추가
- 추가 데이터를 반영한 날씨 카드 Mockup 제작
- 상태 배지와 카드 레이아웃 등 CSS 수정

---

## Part 2. Weather Composition

### 핵심 구현

- `ref`로 검색어, 선택 도시 및 날씨 목록 관리
- `computed`로 도시 검색 결과 계산
- `watch`와 `watchEffect`로 상태 변화 확인
- 검색 결과가 없을 때 안내 화면 표시

### 추가 기능

- 최소 체감온도와 최소 습도를 반응형 상태로 관리
- `computed`를 이용해 검색어와 상세 조건을 함께 적용
- `v-model`로 입력값을 연결해 필터 결과에 반영

---

## Part 3. Weather Component

### 핵심 구현

- 화면을 검색, 필터, 날씨 카드, 공통 레이아웃 컴포넌트로 분리
- Props로 데이터를 전달하고 Emits로 사용자 이벤트 전달
- Slot으로 공통 카드 레이아웃 재사용
- 컴포넌트별 `<style scoped>` 적용

### 추가 기능

체감온도·습도 필터를 `SearchFilter` 컴포넌트로 분리하고, Props와 Emits를 통해 검색 조건과 `apply-filter` 이벤트를 부모에 전달했습니다.

---

## Part 4. Weather Router

### 핵심 구현

- 대시보드, 전국 지도, 상세보기, 서비스 소개, 404 화면 구성
- `/weather/:cityId` 동적 경로로 도시 상세 화면 연결
- `router.push()`를 이용한 상세 페이지 이동
- Lazy Loading, Catch-all Route, Navigation Guard 적용

### 추가 기능

`WeatherMapView`를 추가해 국내 10개 도시의 위치와 현재 기온을 지도 형태로 표시했습니다. 지도에서 도시를 선택하면 해당 도시의 상세 화면으로 이동합니다.

---

## Part 5. Weather Store

### 핵심 구현

- Pinia를 이용해 여러 화면에서 공통 상태 공유
- `configStore`에서 섭씨·화씨 단위 관리
- `filterStore`에서 체감온도·습도 조건 관리
- 입력 중인 조건과 실제 적용된 조건을 분리

### 추가 기능

컴포넌트 내부에서 관리하던 체감온도·습도 필터를 Store로 이동했습니다. 이를 통해 화면 이동 후에도 필터 조건과 온도 단위가 유지되도록 구성했습니다.

---

## Part 6. Weather Axios

### 핵심 구현

- Axios로 국내 10개 도시의 실시간 날씨 요청
- 날씨와 대기질 API를 함께 호출해 상세정보 구성
- `Promise.all()`을 이용한 병렬 요청
- API 응답 정규화 및 Loading·Error 상태 처리
- API Key를 환경변수로 관리

### 추가 기능

Air Pollution API를 추가해 상세 화면에서 대기질 등급, 미세먼지, 초미세먼지 정보를 제공했습니다.

---

## Part 7. Weather UI Library

### 핵심 구현

Element Plus를 적용해 입력 요소와 사용자 상태 안내 UI를 통일했습니다.

- `el-input`: 도시 및 상세 조건 입력
- `el-button`: 검색, 초기화, 상세보기
- `el-switch`: 섭씨·화씨 단위 전환
- `el-tag`: 기온별 상태 표시
- `el-skeleton`: API Loading 상태
- `el-alert`: API 요청 실패 안내
- `el-empty`: 검색 결과 없음 안내

# 활동 내용 및 배운 점

날씨 Mockup 제작부터 컴포넌트 분리, 화면 전환, 전역 상태 관리, 외부 API 연동과 배포까지 Vue 애플리케이션의 전체 개발 과정을 단계적으로 경험했습니다.

`ref`, `computed`, `watch`를 활용한 반응형 상태 관리와 Props, Emits, Slot을 이용한 컴포넌트 간 통신 방법을 학습했습니다. 또한 Vue Router의 동적 경로, Pinia의 전역 상태 관리, Axios의 비동기 요청 및 응답 처리 방법을 적용했습니다.

API 요청 과정에서는 Loading, Error, Empty 상태를 구분해 사용자에게 현재 상태를 안내했으며, 환경변수로 API Key를 관리하고 Vercel을 통해 프로젝트를 배포했습니다.

기능을 확장할수록 변수명, 이벤트명, Route Parameter와 같은 데이터 전달 규칙을 일관성 있게 관리하는 것이 중요하다는 점을 배웠습니다.

## 트러블슈팅

구현 과정에서 이벤트 버블링, 반응형 변수의 선언 순서, Props와 Emits 이름 불일치, 도시 객체와 Route ID의 데이터 형식 불일치 등의 문제가 발생했습니다. 각 문제를 컴포넌트, 상태, 라우터 영역으로 나누어 확인하고 이벤트 수식어 적용, 선언 순서 변경, 데이터 전달 규칙 통일 등의 방법으로 해결했습니다.

온도 필터에서는 섭씨와 화씨의 비교 기준이 달라지는 문제를 해결하기 위해 내부 데이터를 섭씨로 통일했습니다. API 연동 과정에서는 화면마다 응답 형식이 달라지는 문제를 공통 변환 함수로 해결하고, `Promise.all()`과 `try-catch-finally`를 활용해 병렬 요청과 Loading·Error 상태를 관리했습니다.

## AI 활용 및 직접 구현

프로젝트를 진행하면서 오류의 원인을 찾거나 컴포넌트, Router, Store, API의 전체 구조를 설계하는 데 어려움이 있는 부분은 AI의 도움을 받았습니다. 특히 Props와 Emits의 데이터 전달, Pinia 상태 분리, 동적 Route 구성, API 응답 처리 과정에서 구조를 검토하고 해결 방향을 찾는 데 AI를 활용했습니다. 제안받은 코드는 그대로 사용하지 않고 현재 프로젝트의 변수명과 기능에 맞게 수정한 뒤 실행 결과를 확인했습니다.
날씨 데이터 구성, 도시 검색과 체감온도·습도 필터, 화면 디자인, 컴포넌트 연결, 전국 날씨 지도, 온도 단위 전환, 날씨·대기질 API 연동 및 배포는 직접 구현했습니다. 구현 과정에서 발생한 문제는 AI가 제시한 원인과 해결 방법을 참고해 코드를 수정하고, 각 기능을 직접 테스트하며 프로젝트에 적용했습니다.
